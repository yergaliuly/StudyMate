# Адаптер предметов — контракт этапа 6

`src/services/subjectApi.js` работает через общий `apiClient`: один origin,
cookie-сессия, CSRF для изменений и передача `AbortSignal`.
Это слой запросов; подключение форм реального кабинета выполняется отдельно.

## Методы

```javascript
const { subjects, meta } = await subjectApi.list({ q: '', page: 1, pageSize: 20, signal });
const current = await subjectApi.getById(id, { signal });
const created = await subjectApi.create(values, { idempotencyKey, signal });
const updated = await subjectApi.update(id, { description: '' }, {
  version: current.version,
  signal,
});
await subjectApi.remove(id, { signal });
```

`version` — положительное безопасное целое число из сервера. Для PATCH версия
передаётся в третьем аргументе, поля формы — во втором. Пропущенное поле сохраняется;
пустое описание очищается. Нужны хотя бы одно изменяемое поле и версия.
В POST версия и служебные поля не отправляются. DELETE не содержит тела или версии.

GET, список и PATCH требуют `version` в ответе. У старого сохранённого ответа POST
этапа 5 версия может отсутствовать; адаптер не подставляет вымышленную версию.
Повтор POST может вернуть исторический объект даже после его изменения или удаления.
Перед открытием редактора всегда нужен свежий GET; после создания список следует
перечитать с сервера. `progressPercent: null` сохраняется как `progress: null`,
а `lectureCount` отображается в поле `lectures`.

Адаптер не повторяет изменения автоматически и не меняет состояние интерфейса.
Он передаёт `ApiError` вызывающему коду вместе с кодом, статусом и ошибками полей:

- `SUBJECT_VERSION_CONFLICT`: сохранить черновик, предложить загрузить актуальные
  данные. Не подставлять новую версию и не повторять PATCH автоматически.
- `SUBJECT_TITLE_EXISTS` / `VALIDATION_FAILED`: оставить форму открытой и показать ошибки.
- `SUBJECT_NOT_EMPTY`: оставить карточку; удаление не выполнено.
- `SUBJECT_NOT_FOUND`: сообщить о недоступности предмета и обновить список.
- `AUTHENTICATION_REQUIRED` / `CSRF_INVALID`: проверить сессию и восстановить CSRF.
- Сетевой или некорректный ответ PATCH/DELETE: результат неизвестен; проверить GET
  перед решением о повторе. Для явного повтора создания сохраняются исходные
  данные формы и тот же `Idempotency-Key`.

Данные аккаунта не сохраняются через `subjectStorage` и не смешиваются с демо.
