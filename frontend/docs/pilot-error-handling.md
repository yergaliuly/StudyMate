# Проверка frontend перед закрытым пилотом

Backend-изменения `69b18da` вошли в `main` через PR #43 (`4cb5470`).
Это подтверждение кода в Git; SHA работающего облачного контейнера и runtime-настройки
нужно сверить отдельно после деплоя.

## Поведение интерфейса

- При `429 RATE_LIMITED` интерфейс сохраняет сессию и введённые данные.
  В формах аккаунта, проверке сессии, предметах и чтении материалов учитывается
  `Retry-After` в целых секундах: повтор заблокирован до истечения срока.
  Таймер только обновляет интерфейс и сам не отправляет запрос.
- При ошибке опроса задания наблюдение останавливается. Для продолжения пользователь
  явно повторяет чтение после разрешённого срока; новый POST задания не отправляется.
- После `403 CSRF_INVALID` сначала проверяется `/api/v1/auth/me`, затем получается
  новый CSRF. `401 AUTHENTICATION_REQUIRED` означает гостя, ошибка сети или `429` — нет.
  Первоначальная загрузка приложения сохраняет порядок CSRF → me.
- Формы входа и регистрации сохраняют ввод при восстановлении. Пока проверка не
  завершилась, отправка заблокирована; при ошибке доступна «Повторить проверку формы».
  Изменяющий запрос автоматически не повторяется. Черновики аккаунта возвращаются
  только после подтверждения того же владельца.
- `403 REGISTRATION_CLOSED` отображается как «Регистрация сейчас закрыта».
- Повтор той же неоднозначной операции обработки/генерации использует прежний
  `Idempotency-Key`. Новая генерация с новым ключом требует явного действия пользователя.

Без корректного положительного `Retry-After` показывается сообщение об ограничении,
но срок ожидания не выдумывается. Ожидание хранится в памяти открытого приложения;
сервер остаётся источником ограничений после перезагрузки или в другой вкладке.
Ограничения ИИ-заданий не блокируют чтение уже готовых результатов и не являются
денежным бюджетом.

## Локальная проверка

Из каталога `frontend` (Node.js 24, установленные зависимости и Chromium Playwright):

```sh
node --test tests/*.test.js
npm run build
npx playwright test
npx playwright test --config playwright.dev.config.js
```

Production Playwright использует уже собранный `dist`: после изменения исходников
нужно сначала выполнить `npm run build`. Эти проверки подменяют HTTP-ответы,
не требуют запуска облачного backend и не вызывают R2 или OpenAI.

Результат локального прогона 06.10.2026 для ветки `frontend/pilot-error-handling`
на базе `4cb5470`: 606 Node-тестов, 236 production Playwright и 3 dev StrictMode
прошли. Production-сборка прошла; сохраняется прежнее предупреждение Vite о JS chunk
больше 500 kB. `git diff --check` — без ошибок.

## Проверка после публикации

1. Зафиксировать SHA frontend/backend и настройки действующих ограничений.
2. На согласованном стенде проверить `429` с `Retry-After`: сообщение, сохранность
   формы, отсутствие ранних повторов и выхода из аккаунта. Отдельно — паузу
   опроса уже существующего задания. Не исчерпывать платную квоту ради ошибки.
3. Проверить устаревший CSRF при активной и завершённой сессии: me → csrf,
   сохранность ввода, явный повтор без дублирующего изменения. При отказе проверки
   сессии убедиться, что повторяется только GET, а не исходный POST/PATCH/DELETE.
4. Зафиксировать текущий режим регистрации. Если включён allowlist — проверить отказ
   для адреса вне списка; при открытой регистрации — создание нового тестового аккаунта
   и понятный отказ повторной регистрации. Не менять режим только ради этой проверки.
5. Зафиксировать, какие пункты прошли с настоящим backend, а какие только в тестах.

По итогам совместного прохода 06.10.2026 опубликованный frontend уже проверен для
входа, восстановления после reload, предметов (создание, поиск, просмотр,
редактирование, конфликт двух вкладок, удаление пустого предмета) и выхода,
включая закрытие доступа в другой вкладке. Это проверка предыдущей публикации,
не новых ограничений; числовые статусы авторизованных запросов отдельно не записывались.
