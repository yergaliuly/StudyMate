# Frontend — зона участника 1

React + Vite + JavaScript, собственный CSS. Подключены регистрация, вход,
проверка серверной сессии и выход. Реальный кабинет показывает профиль из `/auth/me`,
серверный список предметов с поиском/пагинацией, создание, просмотр, редактирование
с проверкой версии и удаление пустых предметов. При конфликте сохраняется черновик;
после потери ответа результат изменения проверяется отдельным GET. Демо открывается
явно и хранит свои предметы отдельно в браузере. Подключены список материалов,
квота, загрузка PDF, наблюдение за обработкой и просмотр извлечённого текста.

Оригинальный PDF можно скачать из панели «Обработка и текст» кнопкой
«Скачать оригинал PDF». Для сохранённого файла скачивание доступно независимо
от результата извлечения текста. Каждый клик запрашивает свежую подписанную ссылку
со сроком действия 60 секунд; имя скачиваемого файла по контракту — `material.pdf`.
Это скачивание оригинала, а встроенный просмотр PDF пока не подключён.
После ошибки повтор выполняется вручную; закрытие панели отменяет ожидание ссылки.

В той же панели кнопка «Переименовать материал» открывает форму со свежей версией
названия с сервера. Название — от 1 до 160 UTF-16 символов после нормализации пробелов.
При конфликте или потере ответа черновик сохраняется: сначала нужно загрузить актуальную
версию, сравнить названия и явно выбрать данные для следующего сохранения.
Выбор версии сам по себе не отправляет PATCH. Черновик хранится только в памяти текущего
аккаунта, переживает закрытие панели и восстановление той же сессии; перезагрузка страницы
или явный выход его очищают. Переименование меняет название материала, а имя исходного
PDF сохраняется. Ошибка не вызывает автоматического повторного сохранения.

На карточке материала доступно удаление с подтверждением актуального названия
и предупреждением об удалении связанных учебных данных. Ответ `202` запускает
наблюдение за очисткой: файл продолжает занимать место до её завершения.
После успешного задания клиент отдельно проверяет отсутствие материала и обновляет
список, предмет и квоту с сервера. Поиск и текущая страница списка сохраняются;
пустая последняя страница переключается на предыдущую.
Если очистка завершилась ошибкой, повтор удаления запускается только по кнопке.
Потерянный ответ сначала проверяется отдельным GET без повторного DELETE.
Закрытие окна прекращает наблюдение, но не отменяет серверную очистку;
кнопка «Проверить удаление» позволяет продолжить с сохранённым сервером заданием.
Открытая панель текста закрывается перед подтверждением удаления.

Кнопка «Конспект» на карточке открывает сохранённый конспект или предлагает создать
первый, если текст PDF уже извлечён. Перед генерацией показывается подтверждение
передачи текста внешнему провайдеру OpenAI, расхода API-баланса и возможных ошибок
в результате. Открытие панели и обновление данных ничего не генерируют.
После запуска клиент наблюдает за заданием и отдельно читает сохранённый результат.
При потере ответа явный повтор сохраняет прежний Idempotency-Key; автоматического
повтора POST нет. Незавершённая попытка хранится в памяти текущего аккаунта и
переживает закрытие панели и восстановление той же сессии. Явный выход или
перезагрузка страницы очищают локальное состояние; серверное задание сохраняется.
Панель показывает сохранённый текст даже при ожидании или ошибке нового задания.
Текст выводится без исполнения HTML, а `fake-local` явно помечается как демонстрация.
Закрытие панели, переход к тексту или удалению материала прекращают наблюдение
и отменяют ожидание запросов.

Кнопка «Редактировать конспект» загружает актуальную версию и открывает текстовый
редактор. PATCH отправляет только текст и номер версии; после сохранения конспект
помечается как отредактированный вручную. Допустим непустой текст до 100 000 UTF-16
символов; сервер убирает пробелы по краям, сохраняя внутренние переносы строк.
При конфликте версий, потере ответа или прерванном сохранении черновик сохраняется:
нужно прочитать состояние сервера, сравнить тексты и явно выбрать версию для редактора.
Выбор сам по себе ничего не сохраняет. «Скрыть редактор» и закрытие панели оставляют
черновик в памяти текущего аккаунта; явный выход и перезагрузка страницы его очищают.

«Создать заново» доступно после завершения предыдущего задания, в том числе с ошибкой
или отменой. Отдельное подтверждение предупреждает о расходе API-баланса и замене
сохранённого текста, включая ручные правки. Только новая подтверждённая генерация
получает новый Idempotency-Key; повтор неизвестного запроса использует прежний ключ.
Если после потерянного ответа конспект отредактировали в другой вкладке, повтор
требует подтверждения уже обновлённой версии и всё равно сохраняет прежний ключ.
Перед запуском проверяются материал и версия конспекта: изменение на сервере требует
нового подтверждения. Во время генерации прежний текст остаётся виден, а редактирование
и следующая генерация недоступны. Старый результат GET после потерянного ответа или
принятого POST не считается подтверждением завершения нового задания.
Открытый редактор блокирует генерацию. Скрытый черновик сохраняется и после генерации
сравнивается с новой версией; неизвестный результат PATCH сначала нужно проверить.
Автоматических повторов PATCH и POST нет; Retry-After учитывается и после закрытия панели.

Браузерные сценарии проверяются с подменой HTTP-ответов. Совместная проверка этих
действий с реальным backend, R2 и провайдером генерации выполняется отдельно.

Из каталога `frontend`: `npm ci`, затем `npm run dev`. Адрес интерфейса —
`http://127.0.0.1:5173`; запросы `/api` идут через Vite proxy на backend
`http://127.0.0.1:8080`. Production preview используется для тестов с подменой API;
dev proxy не является настройкой production-сервера.

Запуск и полный ручной сценарий с backend:
[проверка авторизации](docs/auth-integration-check.md).

Предметы: [методы API](docs/subject-api.md),
[ручная проверка предметов](docs/subjects-integration-check.md).

## Папки

| Путь | Назначение |
| --- | --- |
| `public/` | Статические файлы, которые станут публичными; никогда не хранить здесь лекции студентов |
| `src/app/` | Корневой компонент, маршруты и общий каркас приложения |
| `src/components/layout/` | Sidebar, Header, основной контейнер страницы |
| `src/components/ui/` | Общие кнопки, карточки, поля, диалоги, состояния загрузки |
| `src/pages/` | Страницы; каждая тематическая группа в своей папке |
| `src/styles/` | Палитра, базовые стили, сетка и адаптивность |
| `src/services/` | Работа с API; не вызывать сервер хаотично из каждого компонента |
| `src/context/` | Общее состояние пользователя после выбора схемы авторизации |
| `src/hooks/` | Повторно используемая логика React, только по необходимости |
| `src/mocks/` | Явно демонстрационные данные для разработки без backend |
| `src/utils/` | Форматирование размера файла, дат и другие небольшие функции |
| `src/assets/` | Иконки и изображения интерфейса, но не пользовательские загрузки |
| `tests/` | Node-тесты API-адаптеров и управления сессией |
| `e2e/` | Playwright-проверки интерфейса с подменёнными ответами API |

Файлы `.gitkeep` — обычные пустые файлы, чтобы подготовленные каталоги попали в Git.
Когда в каталоге появится код, соответствующий `.gitkeep` можно удалить.

Будущие названия файлов и порядок их создания: [план frontend](../docs/frontend-plan.md).
Визуальные правила: [дизайн](../docs/design.md).

## Конфигурация

В `.env.example` есть только публичный адрес API. Секретов там нет.
Любую frontend-переменную `VITE_*` нужно считать доступной посетителю сайта.
Пароли базы и ключи R2/ИИ относятся только к серверу.

Не показывайте демонстрационные проценты прогресса как реальные вычисления.
Пока формула прогресса не согласована, используйте подпись «Демо» или уберите процент.

Справка о публичности Vite-переменных: `https://vite.dev/guide/env-and-mode`.
