# StudyMate — frontend

Основной frontend MVP реализован. Завершены восемь этапов: действия с материалами,
конспекты, версии тестов, прохождение, история и проверка сквозного интерфейса.
Исправление параллельной инициализации CSRF вошло в `main` через PR #40.
Следующая работа — подготовка общего запуска frontend и backend по
[плану запуска](../docs/launch-plan.md). Состояние этапов и границы дальнейшей работы
описаны в [плане frontend](../docs/frontend-plan.md).

Карточки, чат по материалу и расширенный кабинет остаются за пределами этого MVP.
Для них сначала нужны согласованные API-контракты. В рабочем кабинете материалы
открываются через предметы, история — через «Результаты»; отдельные пункты «Лекции»,
«Карточки» и «Настройки» пока показывают заглушки. Демо-кабинет открывается отдельно.

## Авторизация и предметы

React + Vite + JavaScript, собственный CSS. Подключены регистрация, вход,
проверка серверной сессии и выход. Реальный кабинет показывает профиль из `/auth/me`,
серверный список предметов с поиском/пагинацией, создание, просмотр, редактирование
с проверкой версии и удаление пустых предметов. При конфликте сохраняется черновик;
после потери ответа результат изменения проверяется отдельным GET. Демо открывается
явно и хранит свои предметы отдельно в браузере. Подключены список материалов,
квота, загрузка PDF, наблюдение за обработкой и просмотр извлечённого текста.

Параллельные проверки CSRF в одном экземпляре клиента используют общий незавершённый
GET. Отмена ожидания экраном не обрывает этот запрос: браузер должен завершить обработку
cookie до следующего получения токена. Сброс после входа/выхода инвалидирует прежний
токен; новое получение ждёт завершения старого запроса и читает свежий CSRF.
Изменяющие запросы автоматически не повторяются. React StrictMode остаётся включён.

## Материалы и PDF

Оригинальный PDF можно скачать из панели «Обработка и текст» кнопкой
«Скачать оригинал PDF». Для сохранённого файла скачивание доступно независимо
от результата извлечения текста. Каждый клик запрашивает свежую подписанную ссылку
со сроком действия 60 секунд; имя скачиваемого файла по контракту — `material.pdf`.
Это скачивание оригинала, а встроенный просмотр PDF пока не подключён.
После ошибки повтор выполняется вручную; закрытие панели отменяет ожидание ссылки.

В той же панели кнопка «Переименовать материал» открывает форму со свежей версией
названия с сервера. Название — от 1 до 160 UTF-16 символов после нормализации пробелов.
При конфликте или потере ответа черновик сохраняется: сначала нужно загрузить актуальную
версию, сравнить названия и явно выбрать данные для следующего сохранения.
Выбор версии сам по себе не отправляет PATCH. Черновик хранится только в памяти текущего
аккаунта, переживает закрытие панели и восстановление той же сессии; перезагрузка страницы
или явный выход его очищают. Переименование меняет название материала, а имя исходного
PDF сохраняется. Ошибка не вызывает автоматического повторного сохранения.

На карточке материала доступно удаление с подтверждением актуального названия
и предупреждением об удалении связанных учебных данных. Ответ `202` запускает
наблюдение за очисткой: файл продолжает занимать место до её завершения.
После успешного задания клиент отдельно проверяет отсутствие материала и обновляет
список, предмет и квоту с сервера. Поиск и текущая страница списка сохраняются;
пустая последняя страница переключается на предыдущую.
Если очистка завершилась ошибкой, повтор удаления запускается только по кнопке.
Потерянный ответ сначала проверяется отдельным GET без повторного DELETE.
Закрытие окна прекращает наблюдение, но не отменяет серверную очистку;
кнопка «Проверить удаление» позволяет продолжить с сохранённым сервером заданием.
Открытая панель текста закрывается перед подтверждением удаления.

## Конспекты

Кнопка «Конспект» на карточке открывает сохранённый конспект или предлагает создать
первый, если текст PDF уже извлечён. Перед генерацией показывается подтверждение
передачи текста внешнему провайдеру OpenAI, расхода API-баланса и возможных ошибок
в результате. Открытие панели и обновление данных ничего не генерируют.
После запуска клиент наблюдает за заданием и отдельно читает сохранённый результат.
При потере ответа явный повтор сохраняет прежний Idempotency-Key; автоматического
повтора POST нет. Незавершённая попытка хранится в памяти текущего аккаунта и
переживает закрытие панели и восстановление той же сессии. Явный выход или
перезагрузка страницы очищают локальное состояние; серверное задание сохраняется.
Панель показывает сохранённый текст даже при ожидании или ошибке нового задания.
Текст выводится без исполнения HTML, а `fake-local` явно помечается как демонстрация.
Закрытие панели, переход к тексту или удалению материала прекращают наблюдение
и отменяют ожидание запросов.

Кнопка «Редактировать конспект» загружает актуальную версию и открывает текстовый
редактор. PATCH отправляет только текст и номер версии; после сохранения конспект
помечается как отредактированный вручную. Допустим непустой текст до 100 000 UTF-16
символов; сервер убирает пробелы по краям, сохраняя внутренние переносы строк.
При конфликте версий, потере ответа или прерванном сохранении черновик сохраняется:
нужно прочитать состояние сервера, сравнить тексты и явно выбрать версию для редактора.
Выбор сам по себе ничего не сохраняет. «Скрыть редактор» и закрытие панели оставляют
черновик в памяти текущего аккаунта; явный выход и перезагрузка страницы его очищают.

«Создать заново» доступно после завершения предыдущего задания, в том числе с ошибкой
или отменой. Отдельное подтверждение предупреждает о расходе API-баланса и замене
сохранённого текста, включая ручные правки. Только новая подтверждённая генерация
получает новый Idempotency-Key; повтор неизвестного запроса использует прежний ключ.
Если после потерянного ответа конспект отредактировали в другой вкладке, повтор
требует подтверждения уже обновлённой версии и всё равно сохраняет прежний ключ.
Перед запуском проверяются материал и версия конспекта: изменение на сервере требует
нового подтверждения. Во время генерации прежний текст остаётся виден, а редактирование
и следующая генерация недоступны. Старый результат GET после потерянного ответа или
принятого POST не считается подтверждением завершения нового задания.
Открытый редактор блокирует генерацию. Скрытый черновик сохраняется и после генерации
сравнивается с новой версией; неизвестный результат PATCH сначала нужно проверить.
Автоматических повторов PATCH и POST нет; Retry-After учитывается и после закрытия панели.

## Версии тестов

Кнопка «Тесты» на карточке материала открывает список сохранённых версий с пагинацией.
Каждая версия содержит 10 вопросов по 4 варианта ответа и имеет собственный UUID.
Просмотр читает конкретную версию через GET; правильные ответы, объяснения и баллы
в просмотре версии отсутствуют и появляются только в разборе завершённой попытки.
Вопросы и варианты выводятся обычным текстом без исполнения
HTML. Тесты с моделью `fake-local` явно обозначены как демонстрационные.

Создание теста доступно для сохранённого PDF с готовым извлечённым текстом. Перед POST
показывается подтверждение передачи текста OpenAI, расхода API-баланса и возможных ошибок
в вопросах. Тест строится по PDF, независимо от ручных правок конспекта. Новая генерация
создаёт новую версию и сохраняет прежние версии и попытки. Просмотр, обновление списка
и восстановление сессии не запускают генерацию.
Перед отправкой клиент повторно проверяет материал и состояние генерации: изменение
после открытия подтверждения требует нового согласия. При потерянном ответе явный повтор
использует прежний Idempotency-Key, даже если GET ещё показывает предыдущее задание.
Новый ключ создаётся только для нового подтверждённого действия после завершения прежнего.

Задание `material.quiz` наблюдается через общий watcher. Его `resultId` — UUID созданного
теста, а не материала: после успеха клиент отдельно читает эту версию и проверяет её
принадлежность материалу, затем обновляет список. Открытый старый тест остаётся на экране;
к новой версии можно перейти отдельно. Прежние версии доступны во время генерации и при
её ошибке. Ошибка обновления не выдаётся за пустой список; ранее загруженный список
помечается как требующий проверки. Retry-After учитывается без автоматических POST.
Закрытие панели, переход к тексту/конспекту, удалению или другому аккаунту прекращают
наблюдение и ожидание ответов. Страница списка, выбранная версия и ключ незавершённой
попытки генерации хранятся в памяти текущего аккаунта: закрытие панели и восстановление
той же сессии сохраняют их; перезагрузка страницы и выход очищают локальное состояние.

## Прохождение и результаты

Кнопка «Начать тест» в открытой версии создаёт попытку именно этой версии, с отдельным
Idempotency-Key. Повтор неизвестного результата начала сохраняет ключ; «Пройти ещё раз»
после завершения создаёт новую попытку с новым ключом. Открытие просмотра и восстановление
панели не отправляют POST. Для прохождения сохранённого теста нужны backend и PostgreSQL;
ИИ, R2 и фоновые задания не вызываются. Готовность нового извлечения текста не требуется.

В каждом вопросе можно выбрать один вариант или сбросить выбор. Перед отправкой показаны
число ответов и пропусков; отправка всех пропусков завершает попытку с нулевым результатом.
Клиент отправляет только UUID вопросов и выбранных вариантов. Баллы и разбор берутся из
сохранённого ответа сервера: правильный вариант, выбор пользователя, объяснение и физические
страницы PDF. Объяснения отображаются как обычный текст, без исполнения HTML.

При неизвестном результате отправки набор ответов фиксируется: можно прочитать попытку
через GET или явно повторить тот же набор. Даже GET с `in_progress` не разрешает менять
неподтверждённую отправку. Конфликт `ATTEMPT_ALREADY_SUBMITTED` открывает сохранённый
результат через GET; первичная ошибка валидации сохраняет выбор и разрешает исправление.
Если исход предыдущей отправки неизвестен, ошибка валидации при повторе не снимает
фиксацию набора ответов.
Повторные нажатия, Retry-After и восстановление CSRF не вызывают автоматическую отправку.
Ошибка чтения скрывает прежний разбор до успешной проверки.

Идентификатор текущей попытки, выбор и данные незавершённого запроса хранятся только в памяти
аккаунта. Закрытие панели, переключение версии и восстановление той же сессии сохраняют их;
при возвращении известная попытка проверяется GET. Запоздалые ответы после закрытия,
смены материала или аккаунта не меняют интерфейс. Перезагрузка страницы и выход очищают
локальный выбор; сервер промежуточные ответы не хранит. При открытой незавершённой попытке
браузер предупреждает о перезагрузке. Сама созданная попытка остаётся на сервере.

## История попыток

Раздел «Результаты» читает историю через GET `/attempts`: сначала новые попытки,
с пагинацией и фильтром статуса. Кнопки на строке истории позволяют выбрать материал
или конкретную версию; фильтры применяются совместно. Из панели тестов доступны переходы
«История материала» и «История этой версии». Смена фильтров сбрасывает страницу и закрывает
выбранную попытку. Пустая история, отсутствие совпадений и ошибка загрузки различаются;
исчезнувшая последняя страница корректируется один раз. Показатели общего прогресса
по истории не вычисляются: `null` незавершённой попытки не отображается как 0%.

Список содержит только краткие сведения. Названия материалов читаются отдельно через
GET, не больше четырёх одновременно, с отменой при смене страницы или фильтра.
При ошибке названия список остаётся доступным с пояснением; удалённый или удаляемый
материал блокирует открытие его попыток. Прежний список после ошибки помечается
как требующий обновления. Retry-After соблюдается без автоматического повтора по таймеру.

«Открыть результат» и «Продолжить» читают выбранную попытку и её материал с сервера,
затем используют общий интерфейс прохождения и разбора. Открытие из истории не создаёт
новую попытку. После отправки история обновляется, а результат остаётся открытым,
даже если завершённая попытка больше не подходит под выбранный фильтр. Ошибка чтения
скрывает прежний разбор; запоздалый ответ другого фильтра, страницы, попытки или аккаунта
не заменяет текущие данные.

Материалы и история используют общие черновики в памяти аккаунта, отдельно для каждого
идентификатора попытки. Выбор и неподтверждённая отправка сохраняются при переходе между
разделами. Просмотр старого прохождения не подменяет текущую попытку той же версии.
После перезагрузки или нового входа историю можно загрузить снова и открыть сохранённый
разбор либо продолжить незавершённую попытку; неотправленный локальный выбор не восстанавливается.
При восстановлении той же сессии сохраняются раздел, фильтры, страница и выбранная попытка;
выход или другой аккаунт очищают локальное состояние. История не обращается к ИИ, R2 или jobs.

## Локальный запуск

Используйте Node.js 24, как в [frontend CI](../.github/workflows/frontend-ci.yml).
Из каталога `frontend`:

```powershell
npm ci
npm run dev
```

При свободном порте интерфейс доступен на `http://127.0.0.1:5173`.
Запросы `/api` идут через Vite proxy на backend `http://127.0.0.1:8080`;
публичный базовый путь API по умолчанию — `/api/v1`. Для рабочего аккаунта запустите
backend по [его README](../backend/README.md). Демо доступно отдельно без backend.
Настройка Vite proxy относится к разработке и не заменяет маршрутизацию API
на production-сервере.

## Автоматические проверки

Node-тесты проверяют API-адаптеры, сессию, черновики и контроллеры действий.
Браузерные тесты используют подменённый API и не подтверждают работу Java,
PostgreSQL, R2 или реального OpenAI. Из каталога `frontend` в PowerShell:

```powershell
node --test (Get-ChildItem tests -Filter *.test.js).FullName
npm run build
npx playwright install chromium
npx playwright test
npx playwright test --config playwright.dev.config.js
```

Обычный Playwright сам запускает production preview на `127.0.0.1:4173`;
перед ним нужна свежая сборка. Отдельная dev-конфигурация запускает Vite на
`127.0.0.1:5175` и проверяет CSRF с React StrictMode и настоящими cookie браузера,
но с подменёнными HTTP-ответами. Оба порта должны быть свободны.
В CI команды и явный список Node-тестов находятся в
[frontend-ci.yml](../.github/workflows/frontend-ci.yml).

Последний зафиксированный кодовый прогон на ревизии `3c52d8f`: 593 Node-теста,
217 браузерных тестов production preview и 3 dev-теста прошли; сборка прошла
с предупреждением о размере chunk больше 500 kB. Это исторический результат,
а не новый прогон в рамках обновления документации.

## Совместная интеграция и запуск

[Сценарий MVP с настоящим backend](docs/mvp-integration-check.md) проходит через
PDF, конспект, тесты, историю, два аккаунта и очистку квоты. Основной проход
использует локальный fake AI и настоящий R2; проверка реального OpenAI выполняется
отдельно после явного разрешения. Сценарий содержит шаблон отчёта.

По отчёту backend от 04.10.2026 на ревизии `405217b` основной цикл с настоящими
Java, PostgreSQL и R2 прошёл с `AI=fake`. У отчёта есть ограничения; он не подтверждает
реальный OpenAI или повторный полный проход после исправления CSRF в PR #40.
Текущий статус и оставшиеся проверки собраны в [общем плане запуска](../docs/launch-plan.md).

Дополнительные инструкции: [проверка авторизации](docs/auth-integration-check.md),
[методы API предметов](docs/subject-api.md),
[проверка предметов](docs/subjects-integration-check.md).

## Конфигурация

`VITE_API_BASE_URL` задаёт базовый путь API на том же origin, по умолчанию `/api/v1`.
Полный URL вида `https://api.example.com` текущий клиент не поддерживает.
Любую frontend-переменную `VITE_*` нужно считать доступной посетителю сайта.
Пароли базы и ключи R2/ИИ относятся только к серверу.

Не показывайте демонстрационные проценты прогресса как реальные вычисления.
Пока формула прогресса не согласована, используйте подпись «Демо» или уберите процент.

Справка: [переменные окружения Vite](https://vite.dev/guide/env-and-mode).
