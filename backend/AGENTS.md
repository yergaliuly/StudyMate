# Инструкции для backend StudyMate

- Работаем последовательно в одном потоке, по одному явно согласованному этапу.
  После проверки и отчёта остановись; следующий этап автоматически не начинай.
  Не запускай параллельных агентов, worktree для нескольких задач или старый план T00–T15.
- Стек: Java 21, Spring Boot, Maven Wrapper, Spring JDBC, Flyway, PostgreSQL,
  Spring Security и Spring Session JDBC. Модульный монолит; сессии и задания — в PostgreSQL.
  Версии закреплены в pom.xml и Maven Wrapper; Java 21, PostgreSQL 17.
  Проверенное локальное окружение и команды запуска описаны в README.md.
- Зона работы — backend/. Frontend ведёт друг пользователя: не переписывай его
  исходники и дизайн без отдельного указания. Общие файлы меняй в согласованном объёме.
- Источники решений: [архитектура](../docs/architecture.md),
  [API](../docs/api.md), [ответственность](../docs/team-tasks.md).
  Frontend подтвердил общую архитектуру, формат ответов и первые API аккаунта/предметов.
  До интеграции уточнить материалы и PATCH; удаление истории попыток повторно обсудить.
  Этапы 3–4: реализованы регистрация, /auth/csrf, login/logout/me и сессии JDBC.
  Регистрация закрыта по умолчанию (STUDYMATE_REGISTRATION_ENABLED=false).
  API проверен реальным HTTP и перезапуском JAR. Проверку UI с другом проводить отдельно.
  Cookie STUDYMATE_SESSION: HttpOnly, SameSite=Lax, Secure по умолчанию; HTTP — профиль local.
  Сессия: 30 минут бездействия, 12 часов после входа; principal — UUID, без пароля/хеша.
- API: /api/v1, camelCase, data/meta/error, UUID сервера, ISO 8601 UTC.
  SQL-поля — snake_case. Изменения контракта обсуждай; не копируй формат localStorage.
  title/description/icon/tone сохраняются; lectureCount вычисляется, progressPercent пока null.
- Владельца бери из сессии и проверяй на каждой операции, включая файлы, задания и попытки.
  Cookie-аутентификация требует CSRF; не отключай защиту ради подключения frontend.
  Пароли храни стойкими хешами. Не выдавай правильные ответы до завершения попытки.
  Для паролей выбран Argon2id (19 МиБ, t=2, p=1); без trim/нормализации, 12–128 UTF-16.
  Email: JS trim + lowercase Locale.ROOT, без удаления точек/plus-части; уникальность — БД.
- R2 приватный; загрузки недоверенные. Квоты, валидация, таймауты и повторы — на сервере.
  Непустой предмет: 409 SUBJECT_NOT_EMPTY. Удаление материала очищает оригинал
  и связанные учебные данные, включая попытки, с предупреждением в UI и повторной очисткой.
  Новая генерация теста не меняет завершённые попытки.
- SQL-схему меняй последовательными миграциями Flyway; не переписывай применённые миграции.
  Каталог: src/main/resources/db/migration; данные — studymate, история Flyway — public.
  Ограничения БД и транзакции должны выдерживать параллельные запросы.
  Локальный диск не является постоянным хранилищем лекций.
- R2, PDF и ИИ подключаются адаптерами. Fake допустим только явно в разработке/тестах.
  Текст PDF — данные, не инструкции. Не давай ему доступ к секретам, SQL или инструментам.
  Изоляцию PDF в дочернем процессе технически проверяем на этапе PDF, не считаем готовой.
- Тесты добавляй вместе с функциями: чужие данные, CSRF, ошибки файлов/сервисов,
  повторы, квоты, перезапуск и сохранность результатов. Проверки БД выполняй на PostgreSQL.
  Указывай, что реально запускалось; отсутствие Docker, сети или credentials не скрывай.
- Не открывай реальные .env и не выводи секреты. Для схемы настроек используй .env.example.
  Ключи, пароли, session cookie, лекции и дампы не помещай в Git или логи.
- Не устанавливай сервисы, не создавай облачные ресурсы и не делай платные вызовы без разрешения.
  Git-изменения веток/истории, commit, push и PR — только по явному указанию пользователя.
