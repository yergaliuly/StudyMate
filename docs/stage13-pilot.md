# Этап 13: проверки и условия закрытого пилота

Состояние на 2026-10-06. **Этап ещё не завершён.** Реализация этой ветки не развёрнута
в Northflank. Проверки не означают разрешения на платный тариф/вызовы или публичную регистрацию.

## Что реализовано

- V12/request_limits: общие PostgreSQL-окна для bootstrap, входа, регистрации,
  запросов аккаунта и новых jobs конспекта/теста; 429 + Retry-After, отказ 503 при сбое БД.
- Резерв генерации в транзакции создания job; replay не расходует квоту повторно,
  rollback не оставляет списания. Failed/cancelled принятые jobs квоту не возвращают.
- Ограничение входа по нормализованному email; в таблице только SHA-256 адреса, не сам
  адрес. Это псевдонимизация, не шифрование. Истёкшие окна очищаются небольшими пакетами.
- Необязательный список разрешённых email. По умолчанию регистрация закрыта.
  Список не подтверждает владельца почты; для первых двух разработчиков после
  создания аккаунтов регистрацию снова закрыть.
- Ошибочный unsafe-запрос без существующей CSRF-сессии не создаёт анонимную сессию.
- Повторяемая проверка логического backup/restore на новой локальной PG17:
  [скрипт](../backend/scripts/Test-DatabaseRestore.ps1), [инструкция](../backend/README.md#проверка-резервной-копии-на-отдельной-локальной-postgresql).

Значения лимитов: [API](api.md#частотные-лимиты--этап-13),
[переменные](../backend/.env.example). Лимит генераций считает задания, а не деньги:
большой PDF требует нескольких вызовов провайдера. Перед настоящим OpenAI нужен отдельный
небольшой согласованный бюджет проверки и контроль usage проекта.

## Фактическое облачное окружение

Локальная проверка завершена: `mvnw.cmd -Ppostgres-it verify` на новой отдельной
`studymate_stage13_release`, Windows / Java 21.0.6 / PostgreSQL 17.2:
**138 модульных + 183 интеграционных = 321 тест**, ошибок и пропусков нет.
Новая БД прошла V1→V12. Восемь сценариев PilotLimitsIT проверяют реальный HTTP,
неверные CSRF/пароли, отсутствие создания сессий ошибочными запросами, лимит одного
аккаунта без блокировки другого, конкурентные экземпляры, сохранение окна после
создания нового сервиса, rollback квот, summary+quiz/replay и очистку окон.
Остальной набор проверяет R2-протокол на stub, PDF child JVM, чужие UUID, квоты,
удаление, ошибки провайдера и перезапуски; настоящих платных вызовов нет.
Положительная регистрация из списка и binding нескольких адресов проверены отдельно.

Промежуточные прогоны выявили несовместимость старой MockMvc-подмены CSRF с реальной
проверкой существующей сессии. Fixtures исправлены: HTTP/bootstrap cookie для JDBC,
настоящий session token repository для unit-среза. Один повторный прогон на накопленной
БД не дождался старого MaterialRestartIT; финальный полный прогон на новой БД прошёл.

После сохранения ключей Northflank перезапустил backend. При запуске наблюдался 503
connection refused; приложение успешно стартовало за 63.696 секунды, подключилось к
PostgreSQL и подтвердило Flyway V11. После старта `/actuator/health` вернул 200/UP,

Наблюдавшееся потребление backend без обработки PDF — примерно 64–72% от 512 МБ.
Обработчик PDF запускается отдельной JVM с heap 256 МиБ; heap не равен RSS.
Одновременная работа parent + worker + native memory требует измерения пика на хостинге.
До него нельзя обещать обработку максимального PDF на этом тарифе. Принятые ограничения
200 страниц / 1 млн символов / 256 МиБ / 60 секунд не снижались, изоляция не отключалась.
Платный переход или дополнительные ресурсы не создавались.

## Резервная копия и восстановление

2026-10-06 13:44 UTC выполнен pg_dump существующего Addon через private CLI forwarding
(external access не включался). Скрипт восстановил копию в новую локальную PG17,
`pg_restore --single-transaction --exit-on-error`, без обращения к рабочей БД на запись.

- Размер архива: 58 253 байта.
- SHA-256: `A3078A41AFBF6D2535758F6CEB4F58664268F5D0D7395AEDE2F45F4F7BEE43D5`.
- Восстановлена Flyway V11; users/subjects/materials/jobs = 0. Облачная БД пока пуста.
- Сессий и атрибутов сессий = 0; непроверенных ограничений = 0.
- Первое восстановление выявило облачное расширение pg_stat_kcache, отсутствующее
  в локальной PG. Финальный скрипт исключает pg_stat_kcache/pg_stat_statements,
  которые используются платформой для мониторинга; прикладные таблицы не исключены.
- Дамп и JSON-отчёт лежат в защищённом каталоге текущего Windows-пользователя вне Git.
  Backend/jobs/maintenance против восстановленной копии не запускались этой проверкой.

Это подтверждает восстановимость текущей пустой облачной схемы. Дополнительно в
14:00–14:03 UTC проверен наполненный **искусственный** набор с отдельного локального
PG17: новая БД на другом локальном сервере, 564 аккаунта, 392 предмета, 153 материала,
457 jobs, 7 конспектов, 81 тест, 60 попыток. Сравнение контрольных сумм строк всех
16 таблиц (включая Flyway, кроме исключённых сессий) совпало. Архив: 457 960 байт,
SHA-256 `E5906FEABDF09827EE701059252434325EC48B476789F6B98E10FAD7166AB0C0`.

Приложение с выключенными R2/AI/jobs/maintenance и регистрацией запущено на loopback
против этой восстановленной копии: health UP, вход 200 с прежним паролем фикстуры,
прежний балл/10 пунктов разбора completed-попытки совпадают с БД, GET quiz не раскрывает
ключи, logout 204. Приложение остановлено. Учебные файлы R2 этим тестом не восстановлены.
Скрипт также проверен при ложных унаследованных PGHOSTADDR/PGSERVICE/PGSERVICEFILE:
он очищает маршрутизацию libpq, принудительно восстанавливает на loopback, затем
возвращает окружение. Совпадающие source/restore порты отклоняются до обращения к БД.
Логический dump не настраивает облачное расписание и не защищает от потери компьютера.

Northflank документирует native dumps, snapshots и расписания. Предлагаемая политика
для согласования: ежедневная копия, хранение 7 дней, ручная перед миграцией, регулярная
проверка восстановления. Включение расписания ждёт проверки стоимости/доступности в
этом Sandbox. Не подтверждено, что backup storage бесплатен. Второй Addon не создавался:
Sandbox допускает один Addon. Источники:
[backup/restore](https://northflank.com/docs/v1/application/databases-and-persistence/backup-restore-and-import-data),
[тарифные ограничения](https://northflank.com/docs/v1/application/billing/pricing-on-northflank).
