# Первый запуск репозитория: Windows, VS Code, GitHub

Это инструкция для ваших локальных действий. Архив сам ничего не публикует и не меняет аккаунты.
Команды выполняются в терминале VS Code в корне распакованной папки `studymate`.
Не размещайте новый проект внутри папки другого Git-репозитория.

## 1. Распаковать и открыть

Распакуйте ZIP, например, в `C:\Projects`, затем откройте папку
`C:\Projects\studymate` через File → Open Folder.
Внутри должны быть `frontend`, `backend`, `docs`, `.github` и этот README проекта.
Откройте Terminal → New Terminal.

```powershell
git --version
```

Если Git не найден, сначала установите Git for Windows и перезапустите VS Code.
До этого следующие команды не выполняйте.

## 2. Различать три настройки

`git config user.name` — подпись автора коммита, не переключатель входа.
`git config user.email` — почта автора и привязка коммита к аккаунту.
Вход в GitHub в VS Code/браузере и сохранённые HTTPS-учётные данные — отдельная авторизация.
Адрес `origin` указывает на репозиторий, но сам по себе не меняет авторизованный аккаунт.

## 3. Настроить автора только для StudyMate

Команда ниже рассчитана на новый проект из архива, в котором ещё нет `.git`.

```powershell
git init -b main
```

Замените примеры СВОИМИ данными до выполнения; кавычки оставьте.
Имя может быть вашим именем или ником — оно не обязано совпадать с логином GitHub.

```powershell
git config --local user.name "YOUR_NAME_OR_NICKNAME"
git config --local user.email "YOUR_GITHUB_COMMIT_EMAIL"
git config --get user.name
git config --get user.email
```

Почта должна быть добавлена и подтверждена в нужном аккаунте GitHub.
Для приватности можно взять предоставленный GitHub адрес `noreply` из Settings → Emails.
Не придумывайте этот адрес вручную и не публикуйте личную почту без необходимости.
Локальные настройки не меняют другие репозитории. Глобальные могут быть переопределены локальными.

Если осознанно нужен новый автор по умолчанию для других проектов, отдельно используйте:

```powershell
git config --global user.name "YOUR_NAME_OR_NICKNAME"
git config --global user.email "YOUR_GITHUB_COMMIT_EMAIL"
```

Для StudyMate локальной настройки достаточно. Существующие коммиты от этого не изменяются.

## 4. Переключить аккаунт GitHub

В браузере войдите в нужный аккаунт GitHub. В VS Code откройте меню Accounts/Учётные записи
(обычно значок профиля внизу слева), выберите старый GitHub-аккаунт и Sign Out/Выйти.
Подтверждайте выход только из нужной учётной записи.
Названия и расположение пунктов могут отличаться в зависимости от версии и расширений.
Вход из расширения GitHub или первый запрос push может открыть браузер: проверьте,
что разрешение выдаёт правильный аккаунт, прежде чем подтверждать.

При HTTPS Git может использовать сохранённый вход через Git Credential Manager,
независимо от того, какой пользователь отображается в меню VS Code.
Если после переключения push всё ещё использует старый аккаунт, откройте в Windows:
Панель управления → Учётные записи пользователей → Диспетчер учётных данных
→ Учётные данные Windows. Найдите запись GitHub старого аккаунта и удалите только её.
Она может называться `git:https://github.com` или содержать логин/дополнительный путь.
Не удаляйте все записи Windows. Это сброс сохранённого входа, не удаление GitHub-аккаунта,
но в других проектах, использующих этот вход, может понадобиться повторная авторизация.
После повторного push войдите через браузер правильным аккаунтом.

Не меняйте SSH-ключи по этой инструкции: дальнейшие команды используют HTTPS.
Не вводите обычный пароль аккаунта как способ Git HTTPS-авторизации; используйте предложенный
браузерный вход. Токены, пароли и коды двухфакторной проверки никому не отправлять.

## 5. Создать пустой репозиторий

В правильном GitHub-аккаунте создайте репозиторий `studymate`.
Выберите владельца внимательно; публичность обсуждается командой.
НЕ добавляйте на сайте README, `.gitignore` или лицензию: начальные файлы уже в архиве.
Скопируйте HTTPS-адрес созданного репозитория.
В GitHub загружаются отдельные файлы и папки после распаковки, а не ZIP-файл.

## 6. Первый коммит и push

Проверьте, что имя и почта правильные. Затем:

```powershell
git add .
git status
```

Просмотрите список: реальные `.env`, ключи, дампы и загруженные PDF не должны добавляться.
После проверки:

```powershell
git commit -m "init: project structure and design reference"
```

Следующий адрес — ШАБЛОН, замените его HTTPS-адресом своего репозитория:

```powershell
git remote add origin https://github.com/YOUR_GITHUB_USERNAME/studymate.git
git remote -v
git push -u origin main
```

При запросе входа проверьте выбранный аккаунт. После успеха обновите страницу репозитория.
Вы должны увидеть `frontend/`, `backend/`, `docs/`, `.github/` и корневые файлы, а не ZIP.

## 7. Первая рабочая ветка

Начальная структура — единственный стартовый push в `main` по этому плану.
Дальнейший код отправляем через ветки и PR; сначала пустую ветку публиковать не нужно.

```powershell
git switch -c feat/frontend-setup
```

После этого добавляем первый код отдельно, проверяем и открываем PR.
Участник 2 клонирует тот же репозиторий и самостоятельно задаёт свою почту/имя локально.
Доступ второму участнику выдаёт владелец репозитория.

## Если ошибка

`remote origin already exists`: сначала `git remote -v`, не добавляйте origin повторно.
`Permission denied ... to OLD_USER`: проверьте сохранённый вход и право записи в репозиторий.
`fetch first` или `non-fast-forward`: на GitHub уже есть коммиты, сначала разобраться с ними.
Не выполнять `git push --force` ради обхода ошибки и не удалять репозиторий без анализа.
`not a git repository`: терминал открыт не в инициализированной папке StudyMate.
Сообщая об ошибке, присылайте только нужный текст/скриншот, скрыв секреты и лишние личные данные.
