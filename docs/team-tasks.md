# Распределение задач

Участник 1 — пользователь, frontend. Участник 2 — backend, PostgreSQL, R2 и ИИ.
Ники GitHub пока не заданы; не подставлять вымышленные аккаунты в настройки review.

| Этап | Участник 1 | Участник 2 | Совместный результат |
| --- | --- | --- | --- |
| Подготовка | Стиль, каркас frontend, план экранов | Выбор backend-стека, модель данных | Общий API-черновик и одинаковая структура репозитория |
| Вход | Формы, сообщения об ошибках | Авторизация и проверки | Студент входит в свой аккаунт |
| Предметы | Карточки и формы | CRUD и проверка владельца | Два аккаунта видят разные предметы |
| Материалы | Загрузка, квота, список | R2, PostgreSQL, извлечение текста | Загрузка и открытие своего PDF |
| Конспект | Состояния и отображение | ИИ, проверка ответа и сохранение | Полученный конспект доступен повторно |
| Тест | Вопросы, ответы, экран результата | Генерация, попытка, проверка | Результат сохранён и проверен сервером |
| Качество | Адаптивность, доступность, тесты UI | Тесты API, прав доступа и ошибок | Полный сценарий проходит у обоих |

## Общее правило готовности

Изменение проверено автором, описано в PR, просмотрено вторым участником и согласовано
с контрактом API. Для архитектурного PR достаточно проверки структуры и документации;
не писать «тесты приложения пройдены», когда приложения ещё нет.

## Общие файлы

`docs/design.md` ведёт участник 1, `docs/api.md` — участник 2 с согласованием участника 1.
Общий README, `.gitignore`, CI и Git-процесс меняются отдельным небольшим PR.
Не редактировать одновременно чужую часть без сообщения второму участнику.

## Что откладываем

OCR сканов, аудиолекции, сложный поиск, онлайн-редактор PDF, социальную сеть, оплату
и продвинутую аналитику. Чат и карточки — после минимального законченного сценария.
