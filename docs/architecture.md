# Архитектура StudyMate

## Статус решений

Это проектная схема первой версии, не описание уже реализованных функций.
Подтверждено: два участника, PostgreSQL, Cloudflare R2, одобренное визуальное направление.
Предлагается для frontend: React + Vite, JavaScript, собственный CSS.
Не выбраны: backend-фреймворк, ИИ-провайдер, хостинг, конкретные версии библиотек.

## Границы системы

```text
Браузер студента
      |
      | запросы приложения, после публикации — HTTPS
      v
Frontend (frontend/) ── API ──> Backend (backend/)
                                  |       |        |
                                  v       v        v
                              PostgreSQL  R2    ИИ-провайдер
                              записи      PDF   обработка текста
```

Frontend не соединяется с PostgreSQL и не хранит секреты R2/ИИ.
Предлагаемая первая загрузка PDF идёт через backend: так проще централизовать проверку
владельца, типа, размера и квоты. Прямую загрузку по подписанному URL можно рассмотреть позже.
Backend выдаёт доступ к скачиванию только после проверки владельца.

## Авторизация

До кодирования форм входа согласовать способ авторизации в `api.md`.
Предлагаемый стартовый вариант: серверная сессия и HttpOnly cookie; единый origin в production,
прокси к API при локальной разработке. Это предложение, не действующая конфигурация.
Предусмотреть Secure в production, осознанную настройку SameSite, защиту изменяющих запросов
от CSRF, срок жизни и инвалидирование сессии. Не считать скрытие кнопки проверкой доступа.

## Загрузка и обработка материала

Студент выбирает свой предмет и PDF. Backend проверяет вход, принадлежность предмета,
формат, размер и остаток квоты. В R2 сохраняется файл, в PostgreSQL — запись о материале.
Затем извлекается текст; интерфейс получает статус `processing`, затем `ready` или `failed`.
Генерация конспекта имеет собственный статус и не должна подменять статус чтения PDF.

Первоначально поддерживать только PDF с извлекаемым текстом. Для скана без текста
показывать понятную ошибку, не обещая OCR. Не хранить файл под небезопасным исходным именем:
сервер создаёт свой ключ, исходное имя остаётся метаданными.

R2 и PostgreSQL не считаются одной общей транзакцией. При сбое загрузки/записи
нужна компенсация: удалить созданный объект либо сохранить состояние для повторной очистки.
Удаление материала должно учитывать и файл, и связанные записи. Квоты считает сервер,
включая параллельные загрузки; интерфейс показывает предоставленное сервером значение.

## Предлагаемая модель данных

| Сущность | Для чего |
| --- | --- |
| users | Учётная запись и безопасное представление данных авторизации |
| subjects | Предмет и его владелец |
| materials | Предмет, владелец, storage_key, размер, текст, статус |
| generation_jobs | Тип генерации, состояние и понятная причина ошибки |
| summaries | Конспект и материал-источник |
| quizzes / questions / options | Тест, вопросы, варианты; правильные ответы только на сервере до проверки |
| attempts / attempt_answers | Попытка студента, выбранные ответы, итог |
| flashcards / conversations / messages | Второй этап; не создавать заранее без необходимости |

Это перечень сущностей, не готовая SQL-схема. Индексы, связи и правила удаления
участник 2 фиксирует в миграциях и проверяет тестами.

## ИИ и доверие к данным

Загруженный текст — источник сведений, но не инструкция для сервера или ИИ.
Не давать тексту лекции права менять системные правила или вызывать действия.
Результат генерации проверяется сервером по ожидаемой схеме. Повторные клики не должны
случайно запускать много платных запросов: нужны блокировка повтора и ограничения частоты.
Ответы и подсказки связываются с материалом. Не выдумывать страницу источника, если
система не сохранила соответствие текста страницам. Пользователю сообщать о передаче
текста внешнему ИИ-сервису и об ограничениях точности до обработки.

## Тестирование и выпуск

Frontend: состояния загрузки/ошибки/пустых данных, клавиатура, адаптивность, основные формы.
Backend: проверка владельца, квоты, ошибки R2 и PDF, проверка ответа ИИ, расчёт результатов.
Совместно: пройти полный минимальный сценарий и попытаться открыть материал другого аккаунта.
Автоматические проверки CI добавляются после появления запускаемых приложений.
В каркасе нет фиктивной проверки, которая якобы подтверждает готовность сайта.

Резервное копирование базы и файлов, сроки хранения, удаление аккаунта, хостинг и лимиты
провайдеров определить перед публичным запуском. Конкретных бесплатных квот этот каркас не обещает.
