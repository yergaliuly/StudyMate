# StudyMate

**Учебный помощник: PDF → конспект → тест → сохранённый результат.**

Основной сценарий первой версии реализован во frontend и backend. Есть аккаунты,
предметы, загрузка и обработка PDF, конспекты, версии тестов, прохождение и история.
Последняя принятая до обновления этой документации версия — PR #40 (`5cdad7e`),
исправляющий первоначальное получение CSRF.

Основной проход с настоящими Java/PostgreSQL/R2 и локальным ИИ `fake` подтверждён
отчётом backend-разработчика от 04.10.2026. Полный сценарий с настоящим OpenAI и
готовность размещения ещё требуют отдельного подтверждения. Текущее состояние,
источники проверок и следующий шаг собраны в [плане общего запуска](docs/launch-plan.md).

![Визуальное направление StudyMate](docs/design/studymate-reference.png)

## Что работает

- Регистрация, вход, выход и восстановление серверной сессии через cookie/CSRF.
- Предметы: создание, поиск, просмотр, редактирование и удаление пустых предметов.
- PDF: загрузка, квота, извлечение текста по страницам, скачивание и переименование.
- Удаление материала с подтверждением, фоновой очисткой и обновлением квоты.
- Конспекты: явная генерация, чтение, ручное редактирование и повторная генерация.
- Тесты: генерация версий, прохождение, серверный подсчёт баллов и разбор ответов.
- История: фильтры, сохранённые результаты и продолжение незавершённых попыток.

Демонстрационный режим отделён от серверного аккаунта. Карточки, чат по материалу,
расширенный кабинет и показатели прогресса относятся к следующему расширению;
демонстрационные данные не являются результатами обучения пользователя.

## Стек и локальный запуск

Frontend — React, Vite, JavaScript и собственный CSS. Backend — Java 21, Spring Boot,
PostgreSQL 17, Flyway и Spring Session JDBC. Оригиналы PDF хранятся в приватном
Cloudflare R2, генерация выполняется на backend через OpenAI либо локальный `fake`.
Точные зависимости зафиксированы в lockfile frontend и конфигурации backend.

Для frontend используйте Node.js 24, как в CI. Из корня репозитория в PowerShell:

```powershell
Set-Location frontend
npm ci
npm run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

Интерфейс доступен на `http://127.0.0.1:5173`; Vite проксирует `/api` на
`http://127.0.0.1:8080`. Для серверного аккаунта backend и PostgreSQL запускаются
отдельно по [инструкции backend](backend/README.md). Оба адреса используют `127.0.0.1`.
Для полного пути PDF нужны также настроенные R2 и фоновые задания.
Регистрация, R2 и ИИ включаются через настройки backend, а не через frontend.

Команды проверок и устройство интерфейса — в [frontend README](frontend/README.md).
Автоматические browser-тесты подменяют API; они не заменяют проход с настоящими
сервисами. Vite dev/preview не являются готовой конфигурацией общего размещения.

## Команда и работа с изменениями

| Роль | Ответственность |
| --- | --- |
| Frontend-разработчик | Интерфейс, адаптивность, API-клиент, проверки UI и сборка |
| Backend-разработчик | Сервер, БД, R2, PDF, ИИ, ограничения, резервные копии и эксплуатация |
| Оба | Контракт API, совместная проверка, выбор размещения и допуск пользователей |

Каждая задача выполняется в отдельной короткой ветке и проходит PR с взаимным review.
Для frontend используется префикс `frontend/`. Коммит, push и создание PR выполняет
владелец изменений; правила описаны в [Git-процессе](docs/git-workflow.md).

## Данные и секреты

Пароли, cookie, API-ключи, дампы базы и пользовательские PDF не входят в Git.
Любая переменная `VITE_*` доступна браузеру; ключи R2/OpenAI и доступ к БД остаются
на backend. Доступ к данным проверяет сервер. Реальная генерация передаёт текст
внешнему провайдеру и расходует API-баланс; она запускается только явным действием.
